# medicube_marketing

에이피알(APR) 메디큐브 **국내 콘텐츠 마케팅** 신입 지원을 준비하며 만든 포트폴리오 저장소입니다.
고객 반응을 공개 데이터로 먼저 확인하고, 그 내용을 숏폼·포스터·CRM·홍보물로 옮긴 과정을 담았습니다.

**먼저 볼 것** → [포트폴리오 PDF · 14쪽 · 16:9 가로형 · v2.4](reports/메디큐브_콘텐츠마케팅_포트폴리오.pdf)

- **2030 · 부스터 글로우** — 리뷰 232건을 읽고 숏폼 30초, 포스터 2종, 자사몰 앱 CRM을 만들었습니다.
- **5060 · 부스터 프로 X2** — GS샵 상품평 221건을 읽고 1주년 방송 기획과 홍보물 2종을 만들었습니다.
- **근거** — 두 프로젝트는 기초 분석 보고서 3편(국내 트렌드 · 글로벌 트렌드 · 피크 주 대조)과 상세 보고서 5편 위에 서 있습니다.

> **에이피알 지원서 제출용 저장소**입니다. `private_submission/`에는 공식 제품 사진을 넣은 최종 시안(PNG·PSD)이 있고, 제품 이미지의 재사용 허락은 확인되지 않아 **광고 집행·SNS·유튜브 게시용이 아닙니다.** 고객용 시안에는 `승인 전 콘셉트`를 표시했고, 실제 집행과 성과는 없습니다.

## 어떻게 만들었나

1. **직접 받은 원자료로 시작** — 네이버 데이터랩 9개, 쇼핑인사이트 3개, 구글 트렌드 CSV 13종, 올리브영 실측 PDF, 리뷰 438건(공식몰 217 · GS샵 221)과 글로우픽 15건. 모든 수치는 원자료에서 다시 계산했고, 검증되지 않은 값은 본문에 쓰지 않았습니다.
2. **고객의 말을 셈으로 바꾸기** — 리뷰를 의미 단위로 하나씩 코딩해, 가장 자주 나온 기대와 불편을 순서대로 세웠습니다.
3. **한 문장으로 좁히기** — 2030은 `고객의 하루 세 장면`, 5060은 `성능이 아니라 사용법에서 막힌다`로 정하고, 그 문장에 맞는 산출물만 남겼습니다.
4. **만든 것과 주장한 것을 구분** — AI로 만든 이미지, 집행 전 시안, 미확정인 편성·가격·성과를 문서마다 표시했습니다.

## 문서 버전 규칙

1. **저장소 안에서는 파일명을 고정**합니다(`worklog.md`, `reports/메디큐브_글로벌_트렌드_분석보고서.md`).
   파일명을 `_v1.1`, `_v1.2`로 바꿔 새 파일로 올리면 Git이 "삭제 + 추가"로 인식해 줄 단위 변경 이력이 끊깁니다.
2. **버전은 문서 안과 Git 태그로** 남깁니다. 각 문서 첫머리에 `버전 · 최종 수정 시각 · 직전 대비 변경 요약 · 버전 이력표`가 있고, 커밋에는 `v1.x` 태그를 찍습니다.
3. **전달 파일명에도 버전을 넣지 않습니다**(2026-11-20 윤서 님 지시). 슬랙·메일로 보낼 때도 `메디큐브_글로벌_트렌드_분석보고서_2026-11-20.pdf`처럼 **날짜까지만** 쓰고, 버전은 문서 첫머리와 Git 태그로만 남깁니다.
