# medicube_marketing

에이피알(APR) 메디큐브 마케팅 직무 지원을 준비하며 진행한 **기업분석·시장 리서치** 기록입니다.
네이버 데이터랩 검색 지수(국내)와 글로벌 1차 출처 검증, 구글 트렌드 실측 CSV 13종을 근거로, 지금 메디큐브의 수요가 어디로 옮겨갔는지와 지원 전략을 정리했습니다.

- **작업 기간**: 2026-11-18 ~ 2026-11-20
- **현재 문서 버전**: worklog `v1.8` · 글로벌 트렌드 분석 보고서 `v1.0` · 글로벌 사전근거 `v1.7` · 데이터랩 보고서 `v1.1` · 자료조사 `v1.0`
- **숫자 원칙**: 모든 수치는 원본 데이터에서 직접 계산했고, 확인하지 못한 값은 "확인 불가/미확인"으로 남겼습니다. 검색 지수는 **검색 관심도**이며 매출·구매력이 아닙니다.

## 문서 버전 규칙

1. **저장소 안에서는 파일명을 고정**합니다(`worklog.md`, `reports/메디큐브_글로벌_트렌드_분석보고서.md`).
   파일명을 `_v1.1`, `_v1.2`로 바꿔 새 파일로 올리면 Git이 "삭제 + 추가"로 인식해 줄 단위 변경 이력이 끊깁니다.
2. **버전은 문서 안과 Git 태그로** 남깁니다. 각 문서 첫머리에 `버전 · 최종 수정 시각 · 직전 대비 변경 요약 · 버전 이력표`가 있고, 커밋에는 `v1.x` 태그를 찍습니다.
3. **전달 파일명에도 버전을 넣지 않습니다**(2026-11-20 윤서 님 지시). 슬랙·메일로 보낼 때도 `메디큐브_글로벌_트렌드_분석보고서_2026-11-20.pdf`처럼 **날짜까지만** 쓰고, 버전은 문서 첫머리와 Git 태그로만 남깁니다.

## 재현

- 데이터랩 엑셀 10개를 `openpyxl`로 전 행 파싱(54주 × 5주제어 × 10파일 = 2,700값)해 보고서 수치를 재계산했습니다.
- 데이터랩 지수는 **키워드 간 상대 지수(최대 100 정규화)** 입니다. 파일마다 기준 키워드가 달라 **파일 간 절대 비교는 하지 않았고**, 파일 안에서의 비중·배수로만 읽었습니다.
- 구글 트렌드 CSV 13종은 원자료 그대로 두고 python `csv`로 전 행(시계열 1,698값 · 관련 검색어 186행 · 지역 177행)을 재계산했습니다. 세트별 값·규칙은 `reports/메디큐브_글로벌_트렌드_분석보고서.md` 00장(파싱 규칙 8개)에 있습니다.
- 파싱 규칙 중 중요한 것: 다중 검색어 `geoMap`은 **비중(%)**(행 합계 100), 단일 검색어 `geoMap`은 **지수**(최고 지역 100), `<1`은 0.5, `급등`(Breakout)은 %로 환산하지 않음, 세트 간 비교는 **medicube 평균=100 상대지수**만.
- 검증: `.md↔.pdf` 숫자 토큰 대조 **불일치 0건**, 29쪽 전 페이지 이미지 검수, 독립 재계산 24항목 일치(보고서 부록 C).

## 한계

- 검색 지수는 **검색 관심도**이며 매출·구매력이 아닙니다. 보고서에는 이 구분을 명시했습니다.
- 구글 트렌드 지역별 값은 국가 내 비율이라 작은 시장이 과대평가될 수 있습니다(캄보디아 100·리투아니아 56 > 영국 54). 그래서 판정 문구는 **'유럽 주요국 1위'**로 한정했습니다. **'유럽 주요국'의 정의(9개국)와 리투아니아 제외 근거**는 `worklog.md` 2.22 · `research/` 문서 **C-7**에 있습니다.
- 국가 간 **절대 검색량 비교는 불가능**합니다. 세트마다 0~100 눈금의 기준이 달라, 3국 비교는 **medicube=100 상대지수**로만 했습니다.
- 일본 `Biodance`(라틴 표기)는 53주 중 30주가 0입니다. 일본어 표기(ビオダンス)가 확인되지 않아 **일본 Biodance 수요는 판정하지 않았습니다**.
- 원인 미확인 급등(미국 4/12·6/21, 영국 10/4, 일본 8/30)은 원인을 쓰지 않고 날짜와 값만 남겼습니다.
- F세트는 `medicube` 단독 조회라 경쟁사 대비 성과는 알 수 없습니다 — 경쟁사 비교는 A·C·J 세트가 담당합니다.
